# 泾渭云测试专家 — 安装与使用操作手册

> 适用对象：泾渭云测试团队成员
> 目标：在**自己电脑的 WorkBuddy** 中安装「泾渭云测试专家」专家，并在**自己电脑的 VS Code** 中以纯 Skill 形式使用该套件。
> 仓库地址：`https://github.com/hansonzhang0606-ux/jwy-testi-expert`

---

## 一、两种方式一览

| 方式 | 形态 | 适用场景 | 仓库目录 |
|------|------|----------|----------|
| **A. WorkBuddy 专家** | 图形化专家（专家中心一键进入） | 日常全流程测试工作，推荐 | `dist/jingweiyun-testing-expert` |
| **B. VS Code 纯 Skill 包** | SKILL.md 技能，在 VS Code 的 AI 助手中调用 | 在 VS Code 内边写代码边跑流水线 | `dist/jwy-testing-expert-skill` |

两种方式的底层能力一致（需求确认 → 代码分析 → 需求脑图/用例 → DMP 转换 → Confluence 归档 + 工时追踪），只是承载环境不同。

---

## 二、前置条件

- **git**：已安装并能访问 GitHub（本仓库为私有/团队仓库，需有读取权限的账号）。
- **WorkBuddy**：最新版（用于方式 A）。
- **VS Code** + 一个**支持 `SKILL.md` 的 AI 编程助手**（用于方式 B，如 Claude Code、CodeBuddy、Cursor、Codex 等）。
- **Python 3.10+**：部分模块脚本（代码分析、脑图生成、工时追踪）需要本地 Python 运行。

---

## 三、第一步：获取套件（每人只需一次）

```bash
git clone https://github.com/hansonzhang0606-ux/jwy-testi-expert.git
# 进入仓库
cd jwy-testi-expert
```

克隆后核心目录说明：

```
jwy-testi-expert/
├── dist/
│   ├── jingweiyun-testing-expert/   # 方式A：WorkBuddy 专家包（含 avatars/expert.png 头像）
│   └── jwy-testing-expert-skill/     # 方式B：VS Code 纯 Skill 包

```

> 后续更新只需在仓库目录执行 `git pull`，再按下方步骤覆盖对应目录即可。

## 四、方式 A：在 WorkBuddy 中安装专家

专家**必须放在固定目录**才能被 WorkBuddy 识别，其他路径无效。

### 1. 复制专家包到固定目录

把 `dist/jingweiyun-testing-expert` 整个文件夹复制到本机专家目录：

- **Windows**
  ```
  %USERPROFILE%\.workbuddy\plugins\marketplaces\my-experts\plugins\jingweiyun-testing-expert
  ```
  即一般位于 `C:\Users\<你的用户名>\.workbuddy\plugins\marketplaces\my-experts\plugins\jingweiyun-testing-expert`

- **macOS / Linux**
  ```
  ~/.workbuddy/plugins/marketplaces/my-experts/plugins/jingweiyun-testing-expert
  ```

一键命令示例（PowerShell）：
```powershell
Copy-Item -Recurse ".\dist\jingweiyun-testing-expert" "$env:USERPROFILE\.workbuddy\plugins\marketplaces\my-experts\plugins\jingweiyun-testing-expert"
```

### 2. 确认头像已就位

复制后请确认 `jingweiyun-testing-expert/avatars/expert.png` 存在（专家头像「泾信」）。若该文件缺失，专家中心将不显示头像。

### 3. 刷新 / 重启 WorkBuddy

- 重启 WorkBuddy，或在「专家中心」刷新。
- 打开 **专家 → 我的专家（my-experts 市场）**，即可看到 **「泾渭云测试专家」**（分类：项目质量；标签：需求测试 / 用例生成 / 工时追踪）。

### 4. 开始使用

进入专家后，可用推荐问法直接启动：

- `开始泾渭云需求测试流程`
- `执行泾渭云代码分析`
- `查看泾渭云工时统计`

## 五、方式 B：在 VS Code 中以 Skill 使用

`dist/jwy-testing-expert-skill` 是一个**标准 SKILL.md 技能包**，可放入任意支持 `SKILL.md` 的 VS Code AI 助手的 skills 目录中使用。

### 1. 复制 Skill 包到对应助手的 skills 目录

把 `dist/jwy-testing-expert-skill` 整个文件夹复制到下方对应目录：

| VS Code AI 助手 | skills 目录 |
|-----------------|-------------|
| **Claude Code**（VS Code 扩展） | 用户级：`~/.claude/skills/`；项目级：`<项目>/.claude/skills/` |
| **CodeBuddy** | 在 CodeBuddy 设置中查看「skills 路径」，放入其用户级 skills 目录 |
| **Cursor** | 项目级：`<项目>/.cursor/skills/`；用户级：`~/.cursor/skills/` |
| **Codex / 其他支持 SKILL.md 的助手** | 对应助手的 skills 目录 |

> 例（Claude Code 用户级）：
> ```bash
> cp -r dist/jwy-testing-expert-skill ~/.claude/skills/
> ```

### 2. 重启 VS Code / AI 助手

让助手重新加载 skills。

### 3. 调用流水线

在 VS Code 的 AI 对话中用以下触发词唤起（助手会自动加载对应 SKILL.md）：

- `开始泾渭云需求测试流程`
- `执行泾渭云代码分析`
- 提及 `step1`～`step5`、`需求确认`、`测试脑图`、`DMP 用例`、`归档`、`工时统计` 等关键词

### 4. 流水线阶段（step1～step5）

| 阶段 | 内容 |
|------|------|
| step1 | 需求确认 |
| step2 | 代码分析（Java/MyBatis、Python、SQL/存储过程、混合栈） |
| step3 | 需求脑图 / 测试用例生成 |
| step4 | XMind → DMP（Excel）用例转换 |
| step5 | Confluence 归档 |

每完成一个实际步骤，需先完成该步骤的**节省工时采集**，方可进入下一步。

工时采集后**会自动进入 MySQL**，无需手动执行同步命令（机制见第六节）：采集脚本在本地记录落盘成功后即同步到 `agent_time_tracking` 表；若当时数据库不可用，专家会在后续会话开始或你提到「同步工时 / 核对工时」时自动回补（幂等，不会重复计行）。

## 六、本机运行配置（重要）

数据库、Confluence 凭据、产物输出目录等**运行时配置仅在本机读取，不随仓库分发**，需各人自行配置：

- **工时追踪 MySQL**：参考 `dist/jwy-testing-expert-skill/time-tracking/README.md` 与 `config/time_tracking_config.yaml`，并按需配置 `team_roster.yaml`（团队名单）与 MySQL 连接。
  首次使用若本机尚无配置，让专家执行（或自行运行）：
  ```bash
  python scripts/init_mysql_config.py --biz-line 泾渭云 --template
  ```
  生成的 `mysql_config.json` 模板由本人按备注填写或向管理员索取，**不要在对话中把密码发给 AI**。
- **Confluence 上传（step5）**：需在对应模块配置 Confluence 访问凭据，详见 `modules/upload-to-confluence/SKILL.md`。
- **产物目录**：每次调用由用户指定**绝对输出目录**，产物落在该目录下。

> 未配置 MySQL 时，纯分析 / 生成类步骤（step1～step4 的本地生成部分）仍可使用，工时先记在本机 `records.jsonl`；**配好后回补即可入库，数据不会丢**。归档（step5）则必须在配置完成后使用。

### 6.1 节省工时如何进入 MySQL（提交即同步 + 回补兜底）

| 路径 | 触发时机 | 说明 |
|------|---------|------|
| **A 提交即同步**（主） | 每步工时确认后 | `secure_record_time_saved.py` 本地落盘成功 → 立即调用 `sync_to_mysql.py` 写入 `agent_time_tracking`，**不等定时任务** |
| **B 提示词回补**（兜底） | 会话开始 / 你提到「同步工时」/ 上次同步告警 | 自动执行 `sync_to_mysql.py --biz-line 泾渭云`，幂等 |
| **定时任务**（可选） | 每日 09:00 / 12:00 / 18:00 | `register_sync_tasks.py --biz-line 泾渭云`；注册与否**不影响**数据入库 |

手工核对/回补（幂等，可重复执行）：

```bash
python scripts/sync_to_mysql.py --biz-line 泾渭云 --dry-run   # 先看不写
python scripts/sync_to_mysql.py --biz-line 泾渭云              # 实际同步
```

### 6.2 工时录错了怎么办（软作废）

同步账号通常**没有 DELETE 权限**（MySQL 1142），已入库记录无法物理删除。此时用**软作废**：

```bash
python scripts/void_time_record.py --biz-line 泾渭云 --id <数据库主键> --reason "原因"   # 最精确
python scripts/void_time_record.py --biz-line 泾渭云 --employee "姓名" --user-story "PRJ-xxxxxxx" --step-code "P4"
# 先预览：末尾加 --dry-run
```

作用：该行工时归零 + `remark` 打 `[作废]` 前缀 + 写入本机作废名单，**后续同步不会再把它写回**。按 SUM 统计时该行贡献为 0，等同删除。需要物理清除请联系数据库管理员。

> 汇总 JWY 工时时应排除 `remark` 含「作废」的行，否则条数会虚高。

## 七、常见问题

| 现象 | 排查 |
|------|------|
| WorkBuddy 专家中心看不到「泾渭云测试专家」 | ① 确认复制到了**固定目录**（`.../my-experts/plugins/jingweiyun-testing-expert`）；② 重启 WorkBuddy；③ 检查 `.codebuddy-plugin/plugin.json` 无 `[TODO]` 占位 |
| 专家无头像 | 确认 `avatars/expert.png` 已随包复制 |
| VS Code 中 skill 不触发 | ① 确认复制到了**正确的 skills 目录**；② 确认所用助手支持 `SKILL.md`；③ 重启 VS Code / 助手 |
| step5 归档失败 | 检查 Confluence 凭据与页面权限配置 |
| 工时统计无数据 | ① 检查 MySQL 配置与 `team_roster.yaml` 名单；② 运行 `python scripts/sync_to_mysql.py --biz-line 泾渭云 --dry-run` 看是否有待同步记录，去掉 `--dry-run` 回补 |
| 工时录错想删除 | **不要执行 DELETE**（同步账号无该权限，会报 MySQL 1142），改用 `void_time_record.py` 软作废，见 6.2 |
| 专家无头像 | 确认 `avatars/expert.png` 已随包复制；若自行运行 `build_packages.py` 重建，头像会由 core 的 `assets/expert.png` 自动还原 |

## 八、更新与验证

- **更新**：`git pull` 后，按第四/五节覆盖对应目录即可。
- **本地验证（可选）**：仓库内含测试与构建脚本，可运行：
  ```bash
  python tools/build_packages.py
  python -m unittest discover -s tests -v
  ```
  构建结果和 SHA-256 清单写入 `dist/MANIFEST.sha256`。

> ⚠️ **改代码请改 `packages/jwy-requirement-pipeline-core/`，不要只改 `dist/`**
> `tools/build_packages.py` 会清空并重建 `dist/`，只落在 dist 的改动会被覆盖丢失（脚本、提示词、内嵌模板 `assets/`、头像均从 core 复制）。
> 正确流程：改 core → 运行 `python tools/build_packages.py` 重建 dist → 再把 dist 同步到本机 WorkBuddy 安装目录。
