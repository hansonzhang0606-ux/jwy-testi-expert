# XMind 测试用例设计方法（5 层纯文本风格）

从需求到可评审测试点的分层方法，以及容易踩的坑。

---

## 一、需求功能点拆解框架（设计前必做）

**目标**：确保需求中每个功能点都被覆盖，不遗漏。

### 步骤 1：功能点穷举

逐条从需求文档中提取**所有功能点**，形成功能清单：

| 功能点 | 来源（需求段落/截图区域） | 优先级 |
|--------|--------------------------|--------|
| 效贷挡板-近12个月销售额判断 | 需求§2.1 | P0 |
| 采集时间窗口校验 | 需求§2.2 | P0 |
| 客户ID查得税号排除规则 | 需求§2.3 | P1 |
| ... | ... | ... |

**穷举原则**：
- 每个动词 = 一个功能点（判断、查询、排除、记录、返回、推送...）
- 每个阈值/条件 = 一个功能点（>=50万、近15天、状态=成功...）
- 每个枚举值 = 一个功能点分支
- 需求中的示例/数据样例 = 必须覆盖的功能点
- 隐含功能点：权限校验、并发控制、日志记录、异常兜底

### 步骤 2：功能点 → L1 业务场景映射

将功能清单按业务流程归组：

```
F01,F02,F03 → L1: 效贷采集记录判断
F04,F05     → L1: 税号查得排除逻辑
F06,F07     → L1: 名单生成与推送
F08         → L1: 异常兜底与降级
```

### 步骤 3：覆盖度自检（设计后必做）

完成测试点设计后，**逐条对照功能清单**：

```
功能点              | 对应 L1→L2→L3    | 用例数 | 覆盖状态
效贷挡板-销售额判断  | 效贷采集→挡板→...  | 6      | ✅
采集时间窗口校验     | 效贷采集→时间窗口→..| 8      | ✅
客户ID查得税号排除   | 效贷采集→客户ID→...| 4      | ✅
税号排除规则        | 税号排除→...       | 0      | ❌ 遗漏！需补
```

**有 ❌ 的必须补齐后再生成文件。**

## 二、测试设计技术矩阵（按功能类型选择）

根据功能点特性，选用合适的测试设计技术：

| 测试设计技术 | 适用功能类型 | 在 XMind 中的体现 | 优先级 |
|-------------|------------|------------------|--------|
| **等价类划分** | 输入域分类、枚举值 | L2 分类，每个等价类一个 C3/C2 | 必做 |
| **边界值分析** | 阈值/范围/区间 | L2 分类下的边界用例（=、±1、极大极小） | 必做 |
| **判定表/决策表** | 多条件组合逻辑 | L2 分类 = 每列条件组合 | 推荐 |
| **状态迁移** | 状态机/流程流转 | L1 业务场景 = 一个状态流转链 | 推荐 |
| **因果图** | 条件间有依赖/互斥 | L2 分类按因果关系分组 | 可选 |
| **错误推测** | 异常/边界经验 | L2「异常场景」分类 | 必做 |
| **场景法** | 端到端业务流程 | L1 业务场景 = 一个完整业务路径 | 必做 |
| **正交实验法** | 多参数组合测试 | L2 分类 = 正交表行 | 可选 |

### 各技术实操指南

#### 1. 等价类划分
将输入域划分为**有效等价类**和**无效等价类**，每个等价类至少1条用例。

```
规则：近12个月销售额 > 50万

L2: 等价类
├── 有效等价类
│   ├── C3("销售额>50万", "51万", "满足，进入分档")
│   ├── C3("销售额远超50万", "9999万", "满足")
│   └── C3("销售额略超50万", "50.01万", "满足（严格大于）")
└── 无效等价类
    ├── C3("销售额=50万", "50万", "不满足（不含等于）")
    ├── C3("销售额<50万", "49.99万", "不满足")
    ├── C3("销售额=0", "0", "不满足")
    └── C3("销售额为空/null", "null", "不满足（异常兜底）")
```

#### 2. 边界值分析
对每个阈值取 **=、+1、-1、极大值、极小值**。

```
规则：近15天-近45天（闭区间[15,45]）

L2: 边界值
├── C2("N=15（下界）", "通过（N=15落入闭区间）")
├── C2("N=14（下界-1）", "不通过（N<15太近）")
├── C2("N=16（下界+1）", "通过（窗口内）")
├── C2("N=45（上界）", "通过（N=45落入闭区间）")
├── C2("N=46（上界+1）", "不通过（N>45太远）")
├── C2("N=44（上界-1）", "通过（窗口内）")
├── C2("N=1（极小值）", "不通过")
└── C2("N=365（极大值）", "不通过")
```

**⚠️ 边界值反例（务必警惕）**
若不明确区间开闭，会写出自相矛盾的用例：

❌ 错误写法：
- 「近15天-1天 → 通过」
- 「14天 → 不通过」
（14天 = 近15天-1天，同一时间点结论却相反）

✅ 正确做法：
1. 先明确：**闭区间 [15,45]**，即 `15 ≤ N ≤ 45` 才通过（N=距今天数）。
2. 再统一用「距今天数 N」表述所有边界。

#### 3. 判定表/决策表
多条件组合，列出**条件桩→动作桩**的真值表，每列一个用例。

```
规则：满足以下任一条件则通过挡板
  A: 近12个月销售额>50万
  B: 近6个月有成功采集记录
  C: 客户在白名单中

L2: 条件组合（判定表）
├── A∧B∧C → C2("三条全满足", "通过")
├── 仅A   → C2("A满足B/C不满足", "通过")
├── 仅B   → C2("B满足A/C不满足", "通过")
├── 仅C   → C2("C满足A/B不满足", "通过")
├── A∧B   → C2("A和B满足C不满足", "通过")
├── A∧C   → C2("A和C满足B不满足", "通过")
├── B∧C   → C2("B和C满足A不满足", "通过")
├── 全不满足 → C2("三条全不满足", "不通过")
└── 全为空/null → C2("数据全部为空", "不通过（异常兜底）")
```

> **3条「满足其一」规则共 2³=8 种基础组合**，每种都要覆盖。

#### 4. 状态迁移法
适用于有状态流转的功能（如订单状态、审批流程）。

```
L1: 订单状态流转
├── L2: 正向流转
│   ├── C2("待支付→已支付（正常支付）", "状态变更为已支付")
│   ├── C2("已支付→已发货", "状态变更为已发货")
│   └── C2("已发货→已完成", "状态变更为已完成")
├── L2: 逆向流转
│   ├── C2("待支付→已取消（用户取消）", "状态变更为已取消")
│   └── C2("已支付→退款中", "状态变更为退款中")
└── L2: 非法流转
    ├── C2("已发货→待支付（非法回退）", "拒绝，状态不变")
    └── C2("已完成→待支付（非法回退）", "拒绝，状态不变")
```

#### 5. 场景法
端到端业务路径，每个 L1 是一条完整业务链。

```
L1: 正常采集→挡板判断→名单生成→推送
L1: 采集失败→重试→成功→挡板判断→推送
L1: 采集成功→挡板拦截→不生成名单→不推送
L1: 采集成功→挡板通过→名单生成→推送失败→重试
```

#### 6. 错误推测法
基于经验补充异常场景：

| 异常类型 | 测试数据 | 预期 |
|---------|---------|------|
| 接口超时 | 请求>30s无响应 | 触发超时兜底 |
| 返回 null | response=null | 视为不满足 |
| 返回空列表 | response=[] | 视为无数据 |
| 数据类型异常 | 金额="abc" | 类型校验拦截 |
| 精度溢出 | 金额=99999999999.99 | 正常处理或拦截 |
| 并发请求 | 同一毫秒2条请求 | 幂等控制 |
| 数据库不可用 | DB连接失败 | 降级/重试 |
| 权限校验 | 无效token | 拒绝访问 |

## 三、分层结构（自顶向下·5层）

```
L0 根（需求名+版本，如【TD-AI】xxx）
└── L1 业务场景（被测业务的整体描述 / 端到端流程）
    └── L2 测试分类（功能模块/规则分类/测试设计技术维度）
        └── L3 测试条件（具体规则/条件，如「近12个月销售额>=50W」）
            └── L4 测试数据（具体输入数据，如「jysj=60万，zysx=80万」）
                └── L5 预期结果（系统应有的行为或输出）
```

### 用例构造函数

| 函数 | 生成层级 | 适用场景 |
|------|---------|---------|
| `C3(条件, 数据, 预期)` | L3→L4→L5 | 条件与数据可拆分 |
| `C2(条件, 预期)` | L3→L4 | 条件与数据一体，省略 L4 |

> **L2 分类下可混用 C3 和 C2**。能拆分条件与数据的用 C3，无法拆分的用 C2。

### ⚠️ 层级控制（关键）
- `C3()` 和 `C2()` **必须直接挂在 L2 分类节点下**。
- **不要**在 L2 和 C3/C2 之间再加一层 `N()` 子分类，否则会产生多余的 L6 层。
- 如需子分类，把子分类提升为 L2（即每个子分类独立作为一个 L2 节点）。

### L2 分类维度（按需取用）
1. **等价类划分**（有效等价类、无效等价类）
2. **参数边界**（金额/数量/长度等的等于/±1/极大值/极小值）
3. **时间窗口**（近 N 天/月，闭区间边界、跨期、跨年）
4. **判定表/条件组合**（多条规则的笛卡尔积）
5. **状态迁移**（正向流转、逆向流转、非法流转）
6. **场景法**（正常路径、异常路径、中断恢复）
7. **数据异常**（null、空、类型错误、精度）
8. **异常场景**（接口超时、并发、环境配置）
9. **兼容与回归**（原逻辑不被影响、上下游联动）

## 四、金额阈值写法
规则「近12个月 > 50万」（严格大于）：
- =50万 → 不满足（不含等于）
- 50.01万 → 满足（+1）
- 49.99万 → 不满足（-1）
- 0 → 不满足
- 极大值 → 满足
- null/空 → 不满足（异常兜底）

---

## 五、组合场景枚举
若有 3 条「满足其一」规则 A/B/C：
- A∧B∧C、仅A、仅B、仅C、A∧B、A∧C、B∧C、全不满足、全为0、全为空

共 8 种基础组合，再叠加「前置通过/不通过」「附加规则满足/不满足」。

---

## 六、异常兜底
接口超时 / null / 空 / 类型异常 → 预期结果明确写：
- 视为不满足 或 挡板拦截 或 触发兜底逻辑（标注是否需业务确认）

---

## 七、用例节点规范（纯文本无前缀）

- L3 节点 = **测试条件**（规则描述，如「近12个月销售额>=50W and <100W」）
- L4 节点 = **测试数据**（具体输入，如「jysj=60万，zysx=80万」）
- L5 节点 = **预期结果**（系统行为，如「使用jysj=60万进行分档」）

**禁止**：在节点文本中加「测试点：」「预期结果：」等前缀（旧版风格，不再推荐）。
**禁止**：把条件、数据、预期塞进同一个节点（如 `金额=50万 → 不满足`）。

## 八、界面文字『』标识（强制）

### 8.1 判断标准（一句话）

**把需求文档/原型里的关键字引用到测试步骤中时，用『』框起来。**

即：这个词在需求文档或原型里有没有对应文字？
- **有** → 框（说明它是被人引用的界面元素）
- **没有**（纯描述、口语化改写、把界面词当动词用）→ 不框

### 8.2 为什么需要

脑图里同时存在两类文字：**需求里的界面关键字**（列头、按钮、枚举值）和**测试描述**。不加区分时：
- `任务状态分别选执行中/解析中/已完成/已停止/失败` —— 读者不知道这是下拉框的选项，还是在描述一段流程
- `展示任务名称/导入文件/数据源(所选值)/总税号数` —— 无法快速确认字段清单与页面是否一致

用『』框起来后，评审时一眼可辨，也能直接对照原型逐项核验。

### 8.3 框 / 不框对照

| 框（需求关键字被引用） | 不框 |
|---|---|
| 需求里的字段名 / 列头 | 把界面词当动词用（`不允许提交任务`、`解析失败`） |
| 需求里的按钮 / 操作入口 | 自行归纳的测试描述（`列表为空，无报错`） |
| 需求里的枚举值 / 下拉选项 | 接口路径 / 接口号（`getSupportedProduct`、1038084） |
| 需求里的弹窗 / 页面 / 菜单名 | 字段码值（`data.ZX301`） |
| 需求里的导出列名 | 测试数据值（税号、金额、日期、文件名） |
| 需求里的提示 / 报错文案片段 | L1 业务场景名 / L2 测试分类名（层级名，即使引用字段也不框） |

> **层级边界（用户明确）**：『』只用于 **L3 及以下**。L1/L2 是归纳用的场景名/分类名，
> 属于「自己的话」，不属于「引用界面文字」，一律保持裸文本：
> L2 写 `任务状态流转`、`停止任务控制`、`清除筛选`、`列表字段展示`，不写 `『任务状态』流转`。

### 8.4 多关键字并列：只写一对『』

**规则（用户明确要求）**：多个关键字用 `/`（或 `、`）并列时，**开头一个『、结尾一个』**，内部用 `/` 分隔。
不要给每个词单独套括号——碎片化括号啰嗦且割裂语义。

```
✅ 『任务名称/导入文件/数据源(所选值)/总税号数/查询进度/任务状态/创建人(中文)/创建时间』
❌ 『任务名称』/『导入文件』/『数据源』(所选值)/『总税号数』/『查询进度』/『任务状态』/『创建人』(中文)/『创建时间』

✅ 展示『任务名称/导入 Excel/数据源』三项
❌ 展示『任务名称』、『导入 Excel』、『数据源』三项

✅ 可下载解析结果 Excel（『税号/明文税号』）
❌ 可下载解析结果 Excel（『税号』/『明文税号』）

✅ 『单税是否查得/单票是否查得/税+票是否查得』三列与接口返回一致
❌ 『单税是否查得』/『单票是否查得』/『税+票是否查得』三列与接口返回一致
```

细则：
- 括号注释（`数据源(所选值)`、`创建人(中文)`）跟在所属词后面，写在『』**内部**，不要另起一对括号。
- `、` 并列统一改写为 `/` 放入同一对『』，全图风格一致。
- 同一控件的字段名 + 选项值 → 两对『』，**不合并**：
  `『任务状态』分别选『执行中/解析中/已完成/已停止/失败』`（外层字段名，内层选项列表）

**不合并的情形**：
- 两个『』之间隔着描述性文字：`『任务状态』分别选『执行中/解析中』`、`点击『停止任务』后『任务状态』变为『已停止』`
- 两个关键字分属不同字段但紧挨：`『覆盖度查询』『执行中』时新增解析任务`（合并会产生歧义）

### 8.5 完整对照示例

```
L1: 筛选与列表展示
└── L2: 任务状态与任务类型筛选                 # L2 层级名：不框
    ├── C2("『任务类型』选『覆盖度查询』",      # L3 起：框
    │      "仅返回『覆盖度查询』任务")
    ├── C2("『任务类型』选『密文税号解析』",
    │      "仅返回『密文税号解析』任务")
    └── C2("『任务状态』分别选『执行中/解析中/已完成/已停止/失败』",
           "各自正确过滤出对应状态的任务")

L1: 任务互斥与停止控制
└── L2: 停止任务控制
    ├── C2("『执行中』任务点击『停止任务』",
    │      "『任务状态』变为『已停止』，停止后续接口派发")
    └── C2("『已完成/已停止/失败』任务",
           "不展示『停止任务』按钮")

L1: 结果导出与下载权限
└── L2: 结果文件生成
    └── C2("导出结果含追加列",
           "『单税是否查得/单票是否查得/税+票是否查得』三列与接口返回一致")
```

对比反例（同样内容，未框关键字 / 碎片化括号）：

```
L1: 筛选与列表展示
└── L2: 任务状态与任务类型筛选
    ├── C2("任务类型选覆盖度查询",                    # ❌ 未框
    │      "仅返回覆盖度查询任务")
    └── C2("任务状态分别选执行中/解析中/已完成",       # ❌ 未框
           "各自正确过滤出对应状态的任务")

└── C2("导出结果含追加列",
       "『单税是否查得』/『单票是否查得』/『税+票是否查得』三列一致")   # ❌ 碎片化，应合并为一对『』
```

### 8.6 校验

生成后跑 `scripts/lint_brackets.py`，检查成对性、嵌套、其他引号误用、
**L1/L2 带『』**、**枚举值列表未包裹**、**碎片化包裹**（均为 ERROR），
以及命中词表但未包裹（HINT，人工判断）。

```bash
python scripts/lint_brackets.py 输出文件.xmind --keywords ui.txt --all
```

> HINT 里属于「动词化用法 / 测试数据 / 自行归纳的描述」的可忽略，不必强行加框。

## 九、UI 展示效果测试维度（强制，最易整类漏掉）

### 9.1 为什么必须单列

需求文档只描述业务规则，几乎不会写「没有数据时长什么样」「名称太长怎么办」「10 万条会不会卡」。
但评审和上线后出问题的，往往正是这些地方。因此**只要需求涉及列表 / 表格 / 详情 / 进度 / 弹窗 / 表单 / 导出，
就必须按下面 7 类过一遍**，挑适用的落成用例。用 5 层结构写，L2 分类名用业务语、不加『』。

### 9.2 七类清单

**① 无数据 / 空状态**
- 首次进入列表无任何数据：显示空状态（插画 + 文案，如『暂无数据』），不白屏、不报错
- 筛选后 0 条：显示「未匹配」提示，且保留已填筛选条件（不清空）
- 分页边界空态：删除末页最后一条 → 回上一页；仅剩一页 → 回空状态；翻到超出范围页码 → 兜底
- 接口返回 `null` / `[]` / 字段缺失 / 类型异常 → 不显示 `undefined`、`null`、`NaN`、`-`
- 关联数据缺失：无创建人、无进度分母、无数据源 → 展示占位符而非空白错位
- 明细为空：主表有数据但明细为空 → 提示「暂无明细」

**② 数据过多 / 超长**
- 单元格超长（任务名 ≥50 字符）：截断省略号 + 悬浮/点击看全文，行高不变
- 列数超出可视区：横向滚动，表头与内容列对齐，不错位
- 每页条数切换：数据量恰为 0 / 1 / 整页 / 整页+1 / 整页-1 时的分页与页码显示
- 大数据量（万级以上）：加载不卡死、有加载态、超时有提示
- 滚动时表头固定、分页器固定、滚动位置在刷新后保持
- 实时刷新（进度类）：列表不跳动、不闪、不重置滚动位置
- 多选/全选：跨页选择是否保留、全选当前页还是全部

**③ 加载态与交互态**
- 首次加载 loading / 骨架屏；手动刷新按钮 loading 且防重复点击
- 请求失败 → 错误提示 + 重试入口，不留白屏
- 按钮禁用态：置灰 + 悬浮说明原因（如『当前有任务执行中』）
- 提交中：禁止关闭弹窗、禁止重复提交、成功后关闭并刷新列表
- 长耗时操作：进度反馈、可取消、取消后状态正确

**④ 数值与格式精度**
- 大数分隔与展示（850430 不变成 8.5043e5）；数量级极大时不溢出
- 百分比：0% / 100% / 超 100% / 分母为 0（除零保护）
- 时间：格式统一（yyyy-MM-dd HH:mm:ss）、时区、跨天跨年
- 长数字/税号：不截断、不丢精度、不变科学计数法（Excel 导出重点）
- 金额与比率：小数位、四舍五入口径、千分位
- 单位与符号：万/亿、正负号、空值与 0 的区分

**⑤ 状态与文案准确性**
- 状态标签文案 + 颜色与真实状态严格一致（执行中/解析中/已完成/已停止/失败）
- 置灰态、只读态、无权限态的视觉区分
- 提示、报错、二次确认弹窗文案完整、可读、无技术术语泄漏
- 文案过长时换行或省略，不撑破容器
- 相同含义在不同位置文案一致（列表 vs 明细 vs 提示）

**⑥ 布局与适配**
- 小屏（1366×768）下列不重叠、按钮不被遮挡
- 浏览器缩放 80% ~ 200% 布局可用
- 侧边栏收起/展开后表格宽度自适应
- 弹窗高度超出视口时可滚动，内容不被裁切、底部按钮始终可见
- 多标签页 / 长时间停留后返回：会话与页面状态正常

**⑦ 边界交互**
- tooltip / 悬浮卡片内容完整，不被父容器裁切
- 下拉选项过多：可搜索、可滚动、支持键盘
- 操作列按钮过多：折叠为「更多」，展开后不越界
- 导出/下载：下载中提示、失败提示、文件过大提示、文件名重复
- 双击/连点、快速切换筛选条件不产生脏数据

### 9.3 写法要求

- **L2 用业务名**，不带方法论词（不写「边界值」「异常场景」），不加『』：
  ✅ `列表空数据展示`、`长文本与列宽自适应`、`分页与每页条数`、`数值与时间格式展示`、`加载与失败态`
- **预期要写清「展示什么」**，不能写「正常显示」：
  ❌ `C2("任务名超长", "正常显示")`
  ✅ `C2("『任务名称』超长（≥50 字符）", "单元格截断显示省略号，悬浮展示完整名称，行高不变")`
- **落位示例**：

```
L1: 筛选与列表展示
├── L2: 列表空数据展示
│   ├── C2("首次进入『极简覆盖度查询』无任何任务",
│   │      "显示空状态提示，不显示表体、不报错")
│   ├── C2("筛选条件命中 0 条任务",
│   │      "显示无匹配结果提示，筛选区已填条件保留")
│   └── C2("删除末页最后一条任务后刷新",
│          "自动回到上一页；仅剩一页时回到空状态")
├── L2: 长文本与列宽自适应
│   ├── C2("『任务名称』超长（≥50 字符）",
│   │      "单元格截断省略号，悬浮展示完整名称，行高不变")
│   └── C2("列数超出可视区域",
│          "出现横向滚动条，表头与内容列对齐不错位")
└── L2: 数值与时间格式展示
    ├── C2("『总税号数』达 85 万级", "按千分位展示，不出现科学计数法")
    └── C2("查询进度分母为 0（总税号数=0）", "进度显示 0% 且不报除零错误")
```
