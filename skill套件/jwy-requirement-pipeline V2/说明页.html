jwy-requirement-pipeline

泾渭云需求全流程「组合编排」Skill 套件 · 说明页
5 步可独立触发 7 个子 skill 已内嵌 团队只需装 1 个 自包含 · 无外部依赖

一句话定位：把「需求文档 → 需求确认 → 代码分析 → 需求脑图 → DMP 用例 → Confluence 归档」整条链路，按 step1~step5 关键字自动调度到对应子 skill，产物统一落到你指定的目录，并用状态文件记录链路进度。

核心特性：本套件为自包含设计——全部 7 个子 skill 已完整内嵌于 skills/ 子目录。团队其他成员只需安装这一个总 skill，无需再单独安装任何子 skill。

5内嵌子 skill 索引

调用规范（重要）

  • 本 skill 的根目录 = 本 SKILL.md 所在目录，安装到任意位置都成立（不写死绝对路径）。
  • 需要调度某子 skill 时：用 Read 工具读取 skills/<子skill名>/SKILL.md，严格按其指示执行（含运行 scripts/ 脚本、参考 references/）。
  • 子 skill 中的 scripts/xxx / references/yyy 相对路径，一律解析为「本 skill 根/skills/<子skill名>/…」。
  • 不要用 Skill 工具去加载外部的、同名子 skill——本套件必须自包含。
  • 子 skill 内部的示例路径（如 D:\需求\2026、仓库路径）仅为演示，运行时由编排层传参覆盖。

6团队安装与依赖

事项说明
安装把整个 jwy-requirement-pipeline 目录放入 ~/.workbuddy/skills/（或团队共享 skill 目录）即可，无需再装任何子 skill。
Python 运行时子 skill 脚本使用托管 Python（如 C:\Users\<用户名>\.workbuddy\binaries\python\versions\3.13.12\python.exe）。团队环境不同时改用本机 Python 3.11+。
Confluence 凭据upload-to-confluence 从 ~/.workbuddy/mcp.json 的 mcpServers.Confluence.env（CONFLUENCE_URL / CONFLUENCE_USERNAME / CONFLUENCE_API_TOKEN）读取。每个成员需在本机配置自己的凭据；未配置时报错提示。
状态脚本本 skill 的 scripts/pipeline_state.py（标准库，无第三方依赖）用于跨步骤状态与 Step4 依赖校验。

7状态脚本用法

# 初始化 / 读取状态（幂等）
python scripts/pipeline_state.py init --output-dir D:\需求\2026\7.16

# 记录某步产物（更新状态文件）
python scripts/pipeline_state.py record --output-dir D:\需求\2026\7.16 --step step3-1 \
  --products "D:\需求\2026\7.16\【泾渭云20260716】xxx_测试脑图.xmind"

# 校验 step4 依赖（退出码 0=允许，3=拒绝；stdout 含 allowed/reason）
python scripts/pipeline_state.py check --output-dir D:\需求\2026\7.16 --step step4

# 取 step3 可复用的 step1/step2 产物路径
python scripts/pipeline_state.py products --output-dir D:\需求\2026\7.16 --step step3-inputs

# 查看完整状态
python scripts/pipeline_state.py status --output-dir D:\需求\2026\7.16

stepId 取值：step1 / step2 / step3-1 / step3-2 / step3-3 / step4 / step5。--products 多个产物用分号分隔。
